VS Code の agent mode では、GitHub Copilot がコードベースを調査し、変更を提案してファイルを編集し、コマンドを実行します。作業は自分のマシンでリアルタイムに進むため、VS Code の Copilot Chat ではツールの呼び出しやファイルの編集状況を確認できます。差分を確認して個々の変更を採用または取り消し、追加のプロンプトを送って作業を調整できます。エディターを離れる必要はありません。

この演習では、次の内容を学びます。

- アクセシビリティエージェントの作業をリアルタイムで監視する。
- 提案されたファイル編集を確認して採用する。
- 作業中のセッションに指示を追加し、ハイコントラストに加えてライトモードの切り替え機能を実装する。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントが、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザー向けに、ライトモードも切り替えられるようにします。新しい会話を始めるのではなく、既存のセッションに指示を追加して作業を広げます。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調査したファイル、実行したコマンド、提案した編集などの各ステップが表示されます。編集内容は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントが作業している間、チャットをスクロールしてツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドなどが表示されます。
3. エージェントがファイルの編集を提案すると、差分がチャット内に表示されます。
   - **Keep** を選択すると変更を採用します。
   - **Undo** を選択すると変更を元に戻し、別の方法を試すようエージェントに任せます。
4. チャット上部の **Files changed** を開くと、このセッションで変更されたファイルを一覧できます。

> [!NOTE]
> ターミナルコマンドの実行などに許可が必要な場合、エージェントは **Allow** を表示して一時停止します。実行してもよいコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。最後に、変更内容の概要が表示されます。

## ライトモードを追加するようエージェントに指示する

ハイコントラストモードができたら、同じ会話にライトモードの切り替え機能を追加します。同じチャットセッションを続けることで、エージェントはそれまでに変更したコンポーネント、スタイルの方針、local storage を使った設定の保存方法などのコンテキストを引き継ぎます。

1. Copilot Chat の入力欄に、次の追加プロンプトを送信します。

    ```plaintext
    よくできました。次に、ハイコントラストの切り替え機能と並べて、ライトモードの切り替え機能を追加してください。ライトモードも同じパターンに従い、local storage に保存して、同じ UI 領域から利用できるようにします。ハイコントラストとライトモードは、それぞれ独立して有効にできるようにしてください。
    ```

2. エージェントはすでに行った変更を確認し、ライトモードを追加する作業を提案します。
3. ハイコントラストのときと同じように、新しい編集を確認し、差分ごとに **Keep** または **Undo** を選択します。
4. エージェントが意図しない方向に進んだ場合は、チャット入力欄の横にある **Stop** ボタンで停止し、追加のメッセージで意図を伝えます。たとえば、切り替え UI のリファクタリングを避けるよう依頼できます。

> [!TIP]
> 作業中のセッションに追加の指示を送ると、最初からやり直すより早く調整できます。たとえば「CSS を簡潔にして、セレクターの重複ではなく CSS 変数を使ってください」「切り替えボタンを3つにせず、ライトモードを既存の設定パネルに統合してください」「両方の切り替えにキーボードショートカットも追加してください」のように依頼できます。

## 変更されたファイルをレビューする

コミットする前に、エージェントが変更した内容を確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストが更新されているはずです。
3. いくつかのファイルを開き、差分を確認します。カスタムエージェントが指示したアクセシビリティのパターン、ARIA 属性、キーボード操作、セマンティック HTML、local storage による設定の保存が反映されていることを確認します。
4. 内容に問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat の agent mode を使い、進行中のセッションを監視して調整しました。ファイルの編集を確認して採用または取り消し、コンテキストを保ったまま追加のプロンプトで作業を広げました。

このレッスンでは、次の内容を学びました。

- エージェントの作業をリアルタイムで監視する。
- 個々のファイル編集を採用または取り消す。
- 作業中のセッションに追加の指示を送る。
