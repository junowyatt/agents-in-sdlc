`quality-checks` スキルで自動チェックを実行し、Playwright MCP でブラウザー上のフィルター動作を確認しました。次は、これらの機能を明確な QA プロセスを持つカスタムエージェントにまとめます。

このレッスンでは、次の内容を学びます。

- カスタムエージェントが命令、スキル、MCP ツールと連携する仕組みを確認する。
- 再利用できる quality assurance プロファイルを作成して確認する。
- QA エージェントを選択し、フィルター機能の Issue に照らして所見をレビューする。

## シナリオ

Tailspin Toys では pull request (PR) を作成する前に、要件、コード品質、自動チェック、テスト範囲、ブラウザー上の動作を一貫して確認したいと考えています。カスタムエージェントを使うと、QA の手順を調整し、再利用できるレポートを作成できます。

## カスタムエージェントとは

カスタムエージェントは、Markdown プロファイルで定義する、Copilot の専門的な役割です。プロファイルには、エージェントの目的、命令、利用可能なツールを記載します。このワークショップでは、`.github/agents/qa.agent.md` に QA の役割を定義し、Copilot CLI で選択します。

ここまでに使ったカスタマイズには、それぞれ異なる役割があります。リポジトリの命令はチームの標準を説明します。`quality-checks` スキルは繰り返し実行するチェックをまとめます。Playwright MCP はブラウザーツールを提供します。QA プロファイルは、これらを使って要件を評価し、所見を報告するよう Copilot に指示します。QA プロファイルは、他のカスタマイズの代わりではなく、新しい会話も必要ありません。

## QA プロファイルを作成する

機能の PR を作成する前に、再利用可能な QA プロファイルを Copilot に作成させます。プロファイルには、実施するチェックと守るべき範囲の両方を定義します。

1. Codespace に戻り、フィルター機能の会話が Interactive モードであることを確認します。
2. 既定のエージェントに、次のカスタムエージェントを作成するよう依頼します。

   ```plaintext
   .github/agents/qa.agent.md に QA という名前のカスタムエージェントを作成してください。機能を Issue と合意済みの要件に照らして確認し、リポジトリの命令に従い、quality-checks スキルを実行し、Playwright MCP を使って動作を検証するようにしてください。テスト範囲に不足があればテストを追加してください。

   各要件を pass、fail、blocked のいずれかで報告し、根拠を示してください。実装コードを変更する前に確認を求め、変更をコミットしたり pull request を作成したりしないでください。

   今はプロファイルだけを作成してください。内容は私がレビューします。
   ```

## プロファイルを確認する

新しいエージェントを使う前に、Copilot が意図した QA の流れと制約を反映したことを確認します。検証だけを行いたいのに、不完全または範囲の広すぎるエージェントが機能を変更する事態を防げます。

1. `/diff` を入力し、`.github/agents/qa.agent.md` を開きます。
2. frontmatter を読みます。`description` は必須です。`name` は省略できますが、含めるとエージェントの表示名が明確になります。
3. プロファイルの命令を読み、QA が要件を起点にし、リポジトリの命令に従い、`quality-checks` スキルと Playwright MCP を使うことを確認します。
4. 根拠を示して報告すること、実装コードの変更前に確認を求めること、コミットや pull request の作成を行わないことを確認します。
5. 責務や制約に不足があれば、続ける前に既定のエージェントに修正を依頼します。

## Issue を基に QA を実行する

Copilot CLI は会話の開始時にプロジェクトのエージェントを読み込みます。プロファイルを作成したら同じフィルター機能の会話を再開し、QA を選択します。これにより、Issue と計画で決めた内容を引き継げます。

1. 次のプロンプトを使って QA エージェントを有効にします。

   ```plaintext
   /agent QA
   ```

> [!NOTE]
> 新しく作成したエージェントは、使用可能なエージェントの一覧にまだ表示されない場合があります。その場合も、上記のコマンドで有効にできます。

2. 次のプロンプトで機能のレビューを依頼します。

   ```plaintext
   Issue と計画で決めた内容に照らして、フィルター機能をレビューしてください。PR を作成する準備はできていますか。
   ```

3. QA エージェントが作業を開始します。
4. 作業が完了したら、エージェントのレポートを読みます。
